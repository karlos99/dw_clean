PostgreSQL "too many clients already" — ops runbook
==================================================

Symptom: UI errors like FATAL: sorry, too many clients already (port 5432).

Immediate relief
----------------
1. Restart Django to drop app-held connections:
     docker compose restart django
2. Check headroom (local or production — set POSTGRES_* / run inside django container):
     docker compose exec django python manage.py postgres_connections --by-client
3. On production host (e.g. 10.130.3.106), same command against that database:
     python manage.py postgres_connections --by-client
4. If still at limit, terminate long-idle app backends (same DB user only):
     python manage.py postgres_connections --terminate-idle 10

Monitoring / alerting
---------------------
Cron or health check (exit 2 when ≥80% of max_connections):
     python manage.py postgres_connections --warn-pct 80

Raw SQL (psql)
--------------
  SHOW max_connections;
  SELECT count(*) FROM pg_stat_activity;
  SELECT usename, application_name, client_addr, state, count(*)
    FROM pg_stat_activity GROUP BY 1,2,3,4 ORDER BY 5 DESC;

Prevention (app config)
-------------------------
- CONN_MAX_AGE: see .env.example (default 60; use 0 as a stopgap if needed).
- GUNICORN_WORKERS / GUNICORN_THREADS: lower if a single Postgres serves many clients.
- Ensure USE_CLICKHOUSE_ANALYTICS=True so charts prefer ClickHouse over PostgreSQL.
